LOADSETU booking acceptance/rejection update

Important MongoDB migration for an existing database:
The previous Booking schema declared `load` unique. The updated workflow keeps rejected booking history so a load can be offered to another transporter. If the existing MongoDB collection has the old unique index, remove it once after backing up the database:

1. Open MongoDB Atlas -> Browse Collections -> your LOADSETU database -> bookings -> Indexes.
2. Find the unique index on `load` (usually named `load_1`) and drop it.

Or use mongosh after selecting the correct database:
  db.bookings.getIndexes()
  db.bookings.dropIndex("load_1")

Only drop the index if it is the old unique single-field `load` index. The Mongoose model now uses a non-unique load index.

Workflow:
- Broker creates a booking request with status Pending and enters the agreed cost.
- The selected truck is temporarily marked unavailable while the transporter responds.
- Transporter dashboard displays the load, factory contact details, agreed price, and Accept / Reject actions.
- Accept changes status to Confirmed and marks the load Booked.
- Reject records an optional reason, reopens the load, and makes the truck available for other matches.
- Factory dashboard refreshes booking updates periodically and displays Pending / Confirmed / Rejected plus transporter phone and WhatsApp contact.
- WhatsApp links open a pre-filled message; the user must press Send in WhatsApp. This implementation does not auto-send WhatsApp messages.

Run backend:
  npm install
  npm run dev

Run frontend:
  npm install
  npm run dev
